### Task 2: Webhook, follows, likes, users API fixes (commit e207481)

- **follows/route POST CR-04**: Gated both `userStats` upserts inside `if (inserted.length > 0)` — prevents counter corruption on repeated follow POST
- **follows/route DELETE CR-05**: Added `.returning({ id: follows.id })` to DELETE; gated stat decrements inside `if (deleted.length > 0)`
- **likes/route CR-10**: Moved review existence check to BEFORE `db.insert(likes)` — prevents orphaned like rows on soft-deleted reviews
- **users/route CR-09**: Wrapped `db.insert(users)` in try/catch; detects PostgreSQL error code `23505` and returns 409 for username conflicts
- **setup-username ME-07**: Added `value.length < 2` check client-side and `minLength={2}` attribute to input

### Task 3: Restaurants, reviews, notifications, users routes (commit 23e5cc4)
- **restaurants/search CR-08**: Added `.filter(Boolean)` after `Promise.all` to remove undefined upsert results; added ME-06 race condition comment
- **restaurants/map HI-09**: Replaced `selectDistinct` with `reviewUserId` (one row per reviewer) with two-step query: collect review metadata from reviews table, then fetch restaurants by ID — yields one pin per restaurant; removed post-query JS dedup loop
- **reviews/[id] GET CR-07**: Removed `eq(reviews.userId, userId)` from GET WHERE clause — any authenticated user can now fetch a review by ID; ownership check retained for PATCH/DELETE
- **reviews/route POST ME-09**: Added `userStats` upsert to increment `reviewCount` after creating a review
- **reviews/[id] DELETE ME-09**: Added `userStats` upsert to decrement `reviewCount` (floored at 0 via GREATEST) after soft-deleting
- **notifications ME-08**: Added `isNull(reviews.deletedAt)` to review fetch WHERE clause — suppresses restaurant names from deleted reviews
- **followers/following HI-05**: Added `.orderBy(asc(users.id))` to both routes for deterministic cursor pagination
- **uploads ME-01**: Added 10MB server-side file size check before `put()` call; returns 413 on violation

### Task 4: Schema and lib fixes (commit b505b6f)
- **schema.ts HI-04**: Added `feedItemsUniqueIdx` — `uniqueIndex('feed_items_unique_idx').on(table.ownerUserId, table.reviewId)` to feedItems table
- **queries.ts HI-04**: Added `.onConflictDoNothing()` to `db.insert(feedItems).values(feedRows)` in `fanOutToFollowers` — makes fan-out idempotent
- **db.ts ME-02**: Replaced `neon(process.env.DATABASE_URL!)` with explicit guard throwing `'Missing required environment variable: DATABASE_URL'`
- **utils.ts LO-07**: Added `if (diff < 0) return 'just now'` after computing diff — handles future timestamps from clock skew

- **follow-button HI-01**: Added `useState(initialState)` for local `currentState`; `onSuccess` callback calls `setCurrentState(data.followState)` from API response — button label updates immediately after follow/unfollow
- **notification-bell HI-08**: Added `queryClient.invalidateQueries({ queryKey: ['notifications'] })` after mark-all-read so panel items reflect read state without waiting for stale-time expiry
- **tag-input LO-01**: Changed `raw.trim()` to `raw.trim().toLowerCase()` in `commitTag` — matches server-side normalization
- **review-card LO-02**: Replaced single `useEffect` with `ResizeObserver` on `bodyRef.current` — rechecks clamped state on element resize (window resize, layout shift)
- **photo-picker ME-05**: Added `previewUrlRef` to track current preview URL for cleanup; unmount effect uses ref (not closure over state) — prevents premature revocation
- **review-composer ME-04/LO-05**: `photoKey` state always initializes as `null`; added `photoChanged` state; payload only includes `photoKey` in PATCH when `photoChanged` is true

### Task 6: Page fixes (commit 18fae3f)

- **[username]/page.tsx HI-02 + HI-06**: Wired `onEdit={(id) => router.push('/reviews/id/edit')}` and `onDelete={(id) => setDeleteTarget(id)}`; added `deleteMutation`; added `<DeleteDialog>`; passed `followState` from profile API to `<FollowButton>` instead of hardcoded `'none'`
