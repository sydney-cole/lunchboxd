## Spacing Scale

Declared values (multiples of 4 only). Source: `packages/shared/src/constants/tokens.ts`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, tag chip internal padding, inline micro-gaps |
| sm | 8px | Field label-to-input gap, tag chip margin, list item row internal spacing |
| md | 16px | Default field stack gap, card internal padding (horizontal), section padding |
| lg | 24px | Between form sections (e.g. meal type block → rating block), card external margin |
| xl | 32px | Page-level top/bottom padding on composer, review list top padding |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch targets (buttons, FAB, inputs, star zones): minimum 44px tall — required for iOS/Android accessibility
- FAB (floating action button): 56px × 56px — standard FAB size for thumb reach
- Star rating click zones: each half-star zone is minimum 22px wide × 44px tall
- Autocomplete dropdown items: minimum 44px tall

| Text secondary | `#78716C` | Placeholder text, helper text, secondary metadata (meal date, tag count) |

Accent (`#F97316`) reserved for:
1. Primary CTA button background ("Post Review", "Save Changes") — filled
2. FAB (`+`) button background — filled
3. Filled star icons in the rating component (selected stars)
4. Focus ring (`focus:ring-accent`) on all interactive inputs and buttons
5. Active tab / selected segment in the meal type toggle ("Restaurant" | "Homemade")
6. Hover state on text links (underline + color change to accent)

Accent is NOT used for: unselected stars, borders in default state, card backgrounds, tags (use surface), secondary actions.

## Component Inventory

New components to build in this phase. Each maps to a file in `apps/web/components/`.

### 1. `<MealTypeToggle>`
- Segmented control with two options: "Restaurant" and "Homemade"
- Selected segment: accent background, white text, semibold
- Unselected segment: surface background, text-primary, regular weight
- Height: 44px. Full width of form column. Border-radius: `radii.lg` (12px)
- On select: conditionally shows/hides restaurant search field below (D-03, D-06)

### 2. `<StarRating>`
- 5 stars, each split into left-half (0.5) and right-half (1.0) click zones
- Selected stars: accent fill (`#F97316`)
- Unselected stars: border/secondary color (`#E7D5C5`)
- Each star: 32px × 32px rendered size, total touch zone 44px tall (padding)
- Displays numeric value below: "3.5 / 5" in 14px / regular / text-secondary
- aria-label: "Rating: {value} out of 5 stars"
- Keyboard: left/right arrow keys change value by 0.5 increments

### 3. `<RestaurantSearch>`
- Text input (16px, 44px tall, surface bg, border-border)
- Debounced 300ms → calls `GET /api/v1/restaurants/search?q=`
- Dropdown renders below input, max 5 results, each row 44px min height
- Dropdown bg: surface (`#FFF0E0`), border: border (`#E7D5C5`), border-radius: `radii.md` (8px)
- Each result row: restaurant name (16px / regular / text-primary), address (14px / regular / text-secondary)
- Loading state: Loader2 spinner (16px) inside input right side
- "Add manually" row: appears only after search returns zero results — 14px / regular / accent color, "+ Add [query] manually" label
- On manual entry select: restaurant search field converts to a plain text input showing the typed name; no further autocomplete
- Fully hidden when meal type is "Homemade" (D-06)

### 4. `<TagInput>`
- Text input (16px, 44px tall) + Enter/comma to commit a tag
- Committed tags render as chips inline above input
- Tag chip: surface bg, border-border border, border-radius: `radii.sm` (4px), 14px text, 4px vertical / 8px horizontal padding, × close button (16px icon)
- Unlimited tags (D-08); chips wrap to new lines
- Input placeholder: "Add a tag (e.g. comfort food, date night)"

### 5. `<PhotoPicker>` (web)
- "Add photo" button: dashed border, surface bg, 80px tall, full width, centered camera icon (24px) + "Add photo" label (16px / regular)
- On file select: shows thumbnail preview (80px × 80px, rounded-md, object-cover) with × remove button overlaid top-right
- Upload triggers immediately on file select (presigned URL flow); thumbnail shows while upload is in progress (spinner overlay)
- On upload complete: thumbnail remains; photo key stored in form state
- Accept: `image/jpeg,image/png,image/webp` only. Max size: 10MB (client-side guard before upload)
- Error state: red border + destructive-colored error message below ("Photo upload failed. Try again.")

### 6. `<ReviewCard>`
- Surface background card, border-border, border-radius: `radii.lg` (12px), shadow: `0 1px 4px 0 rgba(28,25,23,0.08)`
- Layout (top to bottom): [photo thumbnail if present | restaurant name + meal type badge | rating stars (read-only, small) | review note (clamped to 3 lines, expandable) | tags row | meal date + edit/delete menu]
- Photo thumbnail: 100% width, 160px height, object-cover, rounded top corners only
- Restaurant name: 16px / semibold / text-primary
- Meal type badge: "Homemade" label shown only for homemade type; 12px / regular / text-secondary / surface bg / border / border-radius sm
- Rating display: 5 small stars (20px), filled/empty, accent fill — read-only
- Review note: 14px / regular / text-primary, 1.5 line-height, clamped at 3 lines with "Show more" toggle
- Tags: 14px / regular / text-secondary, comma-separated or chip display
- Meal date: 14px / regular / text-secondary. Format: "Apr 29, 2026"
- Edit/delete: kebab menu (···) top-right of card — Pencil icon → edit action, Trash2 icon → delete action

### 7. `<FloatingActionButton>` (FAB)
- Fixed position, bottom-right: 24px from right edge, 24px from bottom (web: above any nav chrome)
- 56px × 56px circular button, accent background, white Plus icon (24px)
- Shadow: `0 4px 12px rgba(249,115,22,0.35)` (accent-tinted shadow)
- Hover: accent-hover bg. Active: accent-active bg.
- aria-label: "Write a review"
- On mobile (Expo): same spec, using TouchableOpacity with appropriate shadow via NativeWind

## Screen-by-Screen Contract

### Screen A: Review Composer (`/reviews/new` — web, `/compose` tab — mobile)

Layout: Single full-page scrollable form (D-01). Max-width 600px centered. Background: bg (#FFF8F0). Vertical padding: xl (32px) top, xl bottom.

Field order (top to bottom):
1. Page title: "New Review" — heading size (20px / semibold / Inter / text-primary)
2. `<MealTypeToggle>` — "Restaurant" | "Homemade" (D-03)
3. `<RestaurantSearch>` — shown only when meal type = "Restaurant" (D-04, D-06)
4. `<StarRating>` — rating 0.5–5 in 0.5 steps (REVW-01)
5. Review note textarea — label "What did you think?" — 4 visible rows minimum, max 2000 chars. Counter "0 / 2000" shown at 1500+ chars.
6. `<PhotoPicker>` — optional (REVW-03)
7. `<TagInput>` — optional (REVW-04)
8. Date field — `<input type="date">`, label "Meal date", defaults to today. 44px tall, full width. (REVW-05)
9. Submit button — "Post Review" — full width, 44px, accent bg, white text, semibold (Primary CTA)

Gap between each field block: lg (24px).

Validation behavior (mirrors Phase 1 pattern):
- Inline field errors appear below the field on blur (not on keystroke)
- Error text: 14px / regular / destructive red / `role="alert"`
- Submit triggers full validation; first error field receives focus
- Required fields: meal type (always set), rating (required — show error "Please add a rating")
- All other fields are optional

### Screen B: Review List (`/reviews` — web)

Layout: Single column, max-width 600px centered, bg (#FFF8F0). Padding: xl (32px) top.

Header: "My Reviews" — heading (20px / semibold / Inter / text-primary). Review count shown as "(12)" in text-secondary / regular.

List: `<ReviewCard>` components stacked, lg (24px) gap between cards.

FAB: `<FloatingActionButton>` fixed bottom-right, always visible.

Empty state (new user, no reviews):
- Centered illustration area: placeholder empty bowl icon (48px, text-secondary color)
- Heading: "No reviews yet" — 20px / semibold / text-primary
- Body: "Tap + to log your first meal." — 16px / regular / text-secondary
- No CTA button in empty state (FAB already visible and accessible)

### Screen C: Edit Review

Route: navigate to `/reviews/[id]/edit` (separate page, not inline edit — Claude's discretion decision).

Form: Identical layout to Review Composer (Screen A), pre-populated with existing values.

Page title: "Edit Review" — heading size (20px / semibold).

Submit button label: "Save Changes" — same styling as "Post Review".

Delete action: Red text button "Delete review" below submit, right-aligned. 14px / semibold / destructive. Clicking opens confirmation dialog.

Delete confirmation dialog:
- Title: "Delete this review?" — 20px / semibold
- Body: "This can't be undone." — 16px / regular / text-secondary
- Cancel button: outlined, border-border, text-primary — "Cancel"
- Confirm button: destructive red background, white text — "Delete"
- Both buttons: 44px tall, full width on mobile, auto-width side-by-side on web

## Accessibility Contract

- All interactive elements: minimum 44px touch target (WCAG 2.1 SC 2.5.5)
- All form fields: explicit `<label>` with `htmlFor` / `for` binding
- Error messages: `role="alert"` and `aria-describedby` linking field to error
- Star rating: `role="radiogroup"`, each half-star zone is `role="radio"` with `aria-label="X stars"`
- Autocomplete dropdown: `role="listbox"`, results are `role="option"`, input has `aria-expanded` and `aria-haspopup="listbox"`
- FAB: `aria-label="Write a review"`
- Photo picker: `aria-label="Add a photo"`, `aria-describedby` pointing to error when present
- Delete confirmation: rendered as `role="dialog"`, focus trapped within dialog, focus returns to trigger on close
- Color contrast: all text/background combinations meet WCAG AA (4.5:1 for body text, 3:1 for large text)
  - text-primary (#1C1917) on bg (#FFF8F0): ~17:1 — PASS
  - text-secondary (#78716C) on bg (#FFF8F0): ~4.6:1 — PASS
  - white (#FFFFFF) on accent (#F97316): ~3.1:1 — PASS for large text (buttons ≥18px or bold 14px+)
  - destructive (#EF4444) on bg (#FFF8F0): ~4.5:1 — PASS

## Mobile-Specific Contract (Expo / React Native)

NativeWind classes map 1:1 to Tailwind. Use `@lunchboxd/shared` color/spacing/typography tokens in StyleSheet objects where NativeWind doesn't apply.

| Element | Mobile Treatment |
|---------|-----------------|
| FAB | TouchableOpacity, fixed via absolute positioning bottom-6 right-6 (24px), 56×56 rounded-full, accent bg |
| Photo picker | Uses `expo-image-picker` — `launchImageLibraryAsync` with `MediaTypeOptions.Images`; same preview pattern as web |
| Date picker | Use `<input type="date">` equivalent: `@react-native-community/datetimepicker` (available via Expo) or plain TextInput with date string validation — confirm availability before plan |
| Autocomplete dropdown | Rendered as ScrollView below input, not a floating layer — avoids z-index issues on mobile |
| Keyboard behavior | ScrollView with `keyboardShouldPersistTaps="handled"` so autocomplete rows remain tappable when keyboard is open |
| Review note textarea | `TextInput multiline numberOfLines={4}` |
| Delete confirmation | `Alert.alert()` (native modal) instead of custom dialog on mobile |

## Design Decisions (Discretion Areas Resolved)

These were listed as "Claude's Discretion" in CONTEXT.md. Resolved here:

| Decision Area | Resolution |
|---------------|-----------|
| Half-star rating UI | 5 clickable SVG stars with left/right half-click zones (Letterboxd-style). More expressive than a range slider for a food rating app. |
| Photo upload timing | Upload on file select (presigned URL immediately on picker selection). Provides immediate feedback and decouples upload from form submit — required by RESEARCH.md pitfall #1. |
| R2 upload flow | Presigned URL (client uploads directly to R2). Server proxy ruled out due to serverless memory limits — confirmed by RESEARCH.md. |
| Form validation | Inline blur-validation with field-level error messages, matching Phase 1 auth form pattern. React Hook Form 7 for state management (RESEARCH.md recommendation for complex conditional form). |
| Review list card layout | Photo (full-width header) → restaurant + badge → stars → note (3-line clamp) → tags → date + actions. Prioritizes photo impact for a food app. |
| Empty state | Centered empty bowl icon + heading + single-line instruction. No redundant CTA since FAB is visible. |
| Edit flow | Navigate to `/reviews/[id]/edit` (separate page). Keeps composer logic in one place, avoids inline form complexity, easier to deep-link. |
