## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge dot positioning (top-0 right-0) |
| sm | 8px | Avatar-to-text gap in notification row, button gap in panel footer |
| md | 16px | Card body padding (p-4), standard element spacing |
| lg | 24px | Section padding, panel horizontal padding |
| xl | 32px | Map page layout gap (list panel to map area) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Bell icon button touch target: 44px minimum (use p-2.5 = 10px all sides on 24px icon = 44px total). Required for mobile and web header targets.
- Notification panel max height: 480px on desktop, 100dvh minus safe-area-inset-top on mobile. Panel scrolls internally via overflow-y-auto.
- Map pin marker: no spacing rule applies — rendered by @vis.gl/react-google-maps Pin component at library defaults.

### Unread Dot

- Color: `#EF4444` (destructive token — acceptable because a red notification dot is a universal convention)
- Size: `w-2 h-2` (8px x 8px)
- Shape: `rounded-full`
- Position: `absolute top-0 right-0` on the bell icon button container
- Visibility: boolean — shown when `hasUnread === true`, hidden otherwise. No count. No animation.

### Border / Divider

- Use `border-border` (`#E7D5C5`) for panel container border, notification row dividers, list card borders.
- Use `border-b border-border` for divider between notification rows (same as author row separator in ReviewCard).

### Shared Pattern: Notification Row

Exact layout (matches D-06 decision):

```
[ avatar 24x24 ] @{actor} {action text} · {relative time}
```

- Avatar: 24x24px rounded-full; fallback = bg-accent/20 circle with 10px initial (same as ReviewCard author row)
- Action text: 14px regular `text-text-primary`; actor username in semibold (`font-semibold`)
- Relative time: 13px regular `text-text-secondary`; separator ` · ` (space-dot-space)
- Row padding: `px-4 py-3` (16px horizontal, 12px vertical)
- Row divider: `border-b border-border` on each row except last
- Unread indicator: left border `border-l-2 border-accent` on unread rows; absent on read rows

### Notification Panel (Web)

- Trigger: Bell icon in `app/(app)/layout.tsx` (imported as Client Component)
- Panel position: `absolute right-0 top-full mt-2` (below bell, right-aligned)
- Panel width: `w-[360px]` on desktop; full-width on mobile viewport (`w-screen max-w-[360px]`)
- Panel max height: `max-h-[480px]`
- Overflow: `overflow-y-auto`
- Panel container: `bg-surface border border-border rounded-[12px] shadow-[0_4px_12px_rgba(28,25,23,0.12)]`
- Header: "Notifications" in 16px semibold `text-text-primary`, padding `px-4 pt-4 pb-3`, `border-b border-border`
- Close behavior: clicking outside panel closes it (same as kebab menu in ReviewCard)
- Mark-read: fires `PATCH /api/v1/notifications/read-all` on panel open; query invalidation clears dot
- Z-index: `z-50` (same as delete dialog backdrop)

### Map Page Layout (Web)

- Layout: two-column on desktop (`flex-row`) — map fills remaining width, list panel is `w-[320px]` fixed right or left
- Map container: `flex-1 h-[calc(100vh-64px)]` (full viewport height minus nav)
- List panel: `w-[320px] overflow-y-auto border-l border-border bg-bg`
- Search input: `w-full px-3 py-2 rounded-[8px] border border-border bg-white text-[14px]` — same pattern as RestaurantSearch component; placeholder: "Search by neighborhood or city"
- Mobile layout: map full screen, list toggled via a "List view" button overlay (bottom-center of map); z-index `z-10` overlay button
- Map default center: `{ lat: 40.7128, lng: -74.006 }` (NYC) — executor must allow this to be configured or user-located in future; for v1, hardcoded default is acceptable
- Map default zoom: `12`

## Interaction Contracts

### Bell Icon — Web

1. Default state: Bell icon (Lucide `Bell`, 20px), `text-text-secondary`, `p-2.5` (44px touch area)
2. Hover state: `text-text-primary`, `bg-bg` background tint (matches kebab menu hover pattern)
3. Unread state: red dot `w-2 h-2 rounded-full bg-destructive absolute top-0 right-0`
4. Open state: panel renders below; `aria-expanded={true}` on trigger button
5. Close: click outside (mousedown handler on document), Escape key
6. On open: fire `PATCH /api/v1/notifications/read-all` immediately; invalidate `['notifications-unread']`
7. Polling: `refetchInterval: 30_000`, `staleTime: 15_000` on `['notifications-unread']` query

### Bell Icon — Mobile

1. Rendered in Profile screen header via `navigation.setOptions({ headerRight: ... })`
2. Icon: `Bell` from `lucide-react-native`, size 22, color matches profile header text color
3. Unread dot: 8px absolute-positioned red circle (same spec as web)
4. Tap: push `NotificationsScreen` onto stack; fire read-all on screen mount

### Notification Panel Scroll

- Loads 20 rows per page (cursor-based, same limit as feed)
- Load-more: IntersectionObserver sentinel at bottom of panel list triggers next page fetch (same pattern as feed IntersectionObserver in Phase 4)
- Loading state: single `Loader2` spinner (16px, `animate-spin`, `text-text-secondary`) centered in panel during initial load
- Error state: inline error message (14px `text-destructive`) with "Retry" text button

### Map — Web Marker Interaction

1. Click marker: open InfoWindow with restaurant name (16px semibold) and "View reviews" text link
2. "View reviews": navigates to `/@{username}` profile? No — at v1, no restaurant aggregation page exists (DISC-V2-01 deferred). InfoWindow shows name only, no action link.
3. InfoWindow: close on outside click (library default behavior)
4. No clustering for v1 (Claude's Discretion: skip MarkerClusterer — too complex for MVP)

### Map — Mobile Marker Interaction

1. Tap marker: show `Callout` with restaurant name (14px semibold)
2. Callout dismisses on tap-away (library default)
3. `tracksViewChanges={false}` on all Markers (performance — mandatory per RESEARCH.md Pitfall guidance)

### Restaurant List — Search

1. Input change fires query with 300ms debounce (same as SearchPage in Phase 3)
2. Minimum 1 character to trigger search (no minimum — neighborhood names can be short; distinguish from user search which had 2-char minimum)
3. Empty query shows all reviewed restaurants (no filter)
4. Results update in place; no page navigation
5. Manual-entry restaurants (null lat/lng) appear in list results with no map pin; no address shown if address is null

## Accessibility

| Element | Requirement |
|---------|-------------|
| Bell button | `aria-label` (dynamic: see copywriting); `aria-expanded` boolean; `aria-haspopup="true"` |
| Notification panel | `role="dialog"` or `role="region"` with `aria-label="Notifications"`; focus trapped while open (same pattern as DeleteDialog) |
| Notification row | `role="article"` or list item — use `<ul>/<li>` for notification list |
| Unread dot | `aria-hidden="true"` — screen reader info carried by `aria-label` on bell button |
| Map markers | Not keyboard-accessible at v1 (Google Maps JS API limitation); map is supplementary to the list view |
| Search input | `aria-label="Search restaurants by neighborhood or city"` |
| Empty state | Rendered as plain text, not hidden with CSS |
