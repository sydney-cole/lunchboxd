## Spacing Scale

Declared values from `packages/shared/src/constants/tokens.ts` — multiples of 4, applies to both web and mobile:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, avatar letter spacing, tag separators |
| sm | 8px | Avatar-to-text gap, button inner padding (vertical), list item gap |
| md | 16px | Card body padding, form field spacing, section content padding |
| lg | 24px | Profile header vertical padding, stats row margin |
| xl | 32px | Between profile header and review list |
| 2xl | 48px | Page top padding (web, non-mobile) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Avatar touch targets on mobile: minimum 44px height (accessibility floor — not a spacing token, applied as explicit `minHeight: 44` on tappable avatar containers)
- FollowButton vertical padding (`py-1.5` = 6px) is a component-internal legacy value — not governed by this phase's spacing scale.

## Typography

Source: `packages/shared/src/constants/tokens.ts` `fontSizes` and `fontWeights`; confirmed in `review-card.tsx` and `auth-card.tsx`.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Heading | 20px | 600 (semibold) | 1.2 | Inter / system | Section headings (e.g. "Reviews", "Followers"), username on profile header |
| Body | 16px | 400 (regular) | 1.5 | Inter / system | Bio text, restaurant names in cards, form inputs, display name on profile header |
| Label | 14px | 400 (regular) | 1.4 | Inter / system | Secondary metadata (date, tags, @username under display name, stats counts) |

Display name on profile header: 16px / regular — same as Body role.
Bio: 16px / regular / 1.5 line-height.
Stats row ("12 followers · 8 following"): 14px / regular.

## Color

Source: `apps/web/app/globals.css` `@theme` block; mirrored in `packages/shared/src/constants/tokens.ts`.

| Role | Hex | Token | Usage |
|------|-----|-------|-------|
| Dominant (60%) | #FFF8F0 | `bg` | Page background, screen background |
| Secondary (30%) | #FFF0E0 | `surface` | Profile card container, review cards, user list items |
| Accent (10%) | #F97316 | `accent` | See reserved-for list below |
| Accent hover | #EA6C10 | `accentHover` | Accent element hover state |
| Accent active | #D96209 | `accentActive` | Accent element active/pressed state |
| Text primary | #1C1917 | `textPrimary` | All primary text |
| Text secondary | #78716C | `textSecondary` | Metadata, secondary labels, empty state body |
| Border | #E7D5C5 | `border` | Card borders, dividers, form input borders |
| Destructive | #EF4444 | `destructive` | Destructive actions only (see below) |
| White | #FFFFFF | `white` | "Follow" button fill text; avatar upload overlay |

**Accent reserved for:**
- Primary "Follow" button fill (state: `none`)
- Letter-avatar background tint (`accent/20` background + `accent` text)
- Hover border on card elements (`hover:border-accent`)
- "Show more / Show less" text link in review body
- Focus ring on interactive elements (`focus:ring-accent`)
- "Save" / "Save changes" primary CTA button fill on edit profile page/screen

Accent is NOT used for: general links, icons, tab bar active state, stats row, bio text.

**Destructive reserved for:**
- Unfollow hover state on FollowButton (when `following` or `friends` state — hover shows red border/text, matching existing FollowButton implementation)
- Like heart icon fill (`fill-destructive`) when liked — existing pattern from review-card.tsx

## Interaction Contracts

### Profile review list pagination

Approach: `useInfiniteQuery` + IntersectionObserver sentinel (same pattern as web feed, Phase 4). On mobile: FlatList `onEndReached` + `onEndReachedThreshold={0.5}`.

Rationale: Reuses existing infinite scroll infrastructure; avoids introducing a different pagination model in this phase.

### Edit profile — save flow

1. User edits bio / display name fields.
2. If avatar selected: `POST /api/v1/uploads` → receive URL.
3. `PATCH /api/v1/users/me` with `{ bio, displayName, avatarUrl }`.
4. On success: navigate back to `/@username` and invalidate `['profile', username]` query.
5. On error: show inline error message below Save button.

### Mobile navigation from profile

- Tap "N followers" or "N following" → push `FollowListScreen` with `{ username, mode: 'followers' | 'following' }`.
- Profile tab shows own profile. Tapping another user's username in feed/search → push `ProfileScreen('username')`.
- Edit Profile button → push `EditProfileScreen`.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Avatar alt text | `alt="{username}'s avatar"` (web); `accessibilityLabel` on Image (mobile) |
| Letter avatar aria | `aria-hidden="true"` on letter span; parent container carries alt |
| Follow button | `aria-label` includes current state: "Follow {username}" / "Unfollow {username}" |
| Stats row links | `aria-label="12 followers"` and `aria-label="8 following"` on anchor/Pressable |
| Edit form | `<label>` elements associated with all inputs; bio textarea has `aria-describedby` for char count if implemented |
| Avatar upload | `<input type="file" accept="image/*">` with visible label "Upload photo"; hidden from AT only when label is adjacent |
| Focus ring | `focus:outline-none focus:ring-2 focus:ring-accent` on all interactive elements (web) |
| Mobile touch targets | Minimum 44px height on all tappable elements |
